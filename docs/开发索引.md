## 2026-11-06：最小页面
- 目标：建立可本地打开的页面框架，暂不实现业务功能。
- 实现：今日概览、饮食记录、训练安排、本周回顾；空状态；计划与实际的说明；响应式样式。
- 技术：HTML、CSS、JavaScript，Node 内置 HTTP 服务，无第三方依赖。
- 自动检查：JavaScript 语法通过；六种导航地址在模拟 DOM 环境检查通过。此检查不是浏览器测试。
- 环境限制：自动 HTTP 访问被执行环境 EACCES 阻止，未完成自动浏览器截图验证。
- 用户验收：用户报告“网站都可以正常打开，没有横向滚动条，没有文字遮挡”，并提供今日概览截图；截图显示通过本地文件方式打开。
- 证据：本轮完整 AI 对话与用户截图；原件由用户保存在并列的竞赛素材文件夹。录屏是否保存尚未确认，不虚构文件名或时间点。
- 对应 Git：本记录随首个提交保存，可用 git log 查看实际提交标识。
- 尚未实现：录入、存储、营养计算、AI 接口、周汇总。
- 待办：后续验证 HTTP 启动方式；按小阶段实现饮食记录。

## 2026-11-12：饮食自由输入估算与查询
- 用户明确要求减少追问，自动估算记录；想吃的内容用于查询，不创建计划。
- 实现双模式、有限食物词表与份量规则、可改克数、描述编辑、日汇总、原文和来源保留。
- 保留训练自由文本识别和手动编辑；训练与饮食本轮仍未提交。
- 自动验证：语法、数量与单位、查询隔离、一次转记录、防重复、编辑替换、取消修改、未来日期拦截、克数重算、删除、刷新、旧记录兼容、存储失败和未知数据。
- 验证方式为模拟 DOM 与代码检查，不等同于真实浏览器测试。
- 待用户验收：双模式布局及操作，尤其是查询不增加摄入、点击后仅增加一次。
- 已知限制：红烧肉等复杂菜暂不支持；未接模型，默认份量和匹配品类均属估算。
- 保留本轮完整对话与实际验收录屏；提交说明须先由用户确认。
